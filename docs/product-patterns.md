# Product patterns used in Agency Ops

The project workspace follows a small set of patterns validated against established CRM and project-management products. Agency Ops intentionally keeps only the parts needed by a small marketing agency.

## Adopted patterns

- **One client — one workspace.** Brief, calls, tasks, deadlines, approvals, reports and activity stay inside one project card.
- **Portfolio attention view.** Search and filters surface active, paused, lead and attention-required projects without mixing client contexts.
- **Project pulse.** The first screen shows urgent tasks, open work, upcoming deadlines, calls, reports and recent activity.
- **Multiple task states.** Tasks move through backlog, doing, review, blocked and done; blocked and overdue work is visible first.
- **Controlled external sharing.** Public report links expose published reports, not internal notes or other client data.

## References

- [Bitrix24 for marketing agencies](https://www.bitrix24.com/solutions/industry/marketing-agency.php) — dedicated client workspaces, tasks, approvals, permissions and portfolio deadline visibility.
- [Bitrix24 Tasks & Projects](https://www.bitrix24.com/tools/tasks_and_projects) — list, deadline, planner, calendar, Kanban and Gantt views.
- [Frappe CRM](https://github.com/frappe/crm) — an all-in-one lead/deal page with activities, notes and tasks plus saved/custom views.
- [Plane](https://github.com/makeplane/plane) — work items, modules, pages and filtered views for project execution.
- [Twenty](https://github.com/twentyhq/twenty) — configurable CRM objects, views and workflows without forcing one rigid data model.

These sources informed the interaction model only; no source code was copied.
