# DigitalRed CRM

Внутренняя CRM и операционная платформа агентства: лиды и квалификация, передача проданного проекта в производство, задачи, обязательные ворота запуска, доказательства, недельные отчёты, эскалации и клиентская ссылка.

## Разделы и права

- **Собственник** видит «Продажи» и «Производство», создаёт и квалифицирует лиды, фиксирует касания, перетаскивает сделки между этапами канбана и переводит выигранную сделку в проект.
- **Проджект** видит только «Производство»: проекты, задачи, передачу, запуск, отчёты, риски и эскалации. API продаж для этой роли закрыт.
- **Исполнитель** видит только проекты, где он назначен менеджером или исполнителем задачи.

В «Производстве» отдельно контролируются просроченные задачи, отчёты, клиентские контакты, открытые эскалации и проекты без следующего действия.

## Контур результата клиента

В каждом проекте есть вкладка «Результат»:

- обязательный паспорт результата: бизнес-цель, KPI, бюджет, логин Direct, Метрика, CRM, оффер, аудитория, ограничения и утверждённая структура кампаний;
- серверный запрет запуска без готового паспорта и закрытого чек-листа;
- ежедневные подтверждённые метрики Direct со статусами `confirmed`, `confirmed_zero` или `unavailable`;
- журнал корректировок с основанием, риском, состоянием до/после и статусом согласования;
- утренний сбор через Yandex Direct API. При недоступности источника изменения не выполняются, а день фиксируется как `unavailable`.

Автокорректировки по умолчанию выключены. Ежедневный сбор формирует доказательный аудит и ставит отклонения на проверку проджекта; стратегию и бюджеты нельзя менять без достаточного объёма данных и зафиксированного основания.

Боковое меню можно свернуть до компактной панели; выбор сохраняется в браузере.

## Запуск

Требуется Node.js 24+. Сервис слушает только `127.0.0.1:8790`; внешний HTTPS завершается в Caddy на `/agency/`.

Данные хранятся в SQLite (`/var/lib/agency-ops/agency-ops.sqlite`) с WAL. Начальные пользователи создаются из `INIT_IVAN_PASSWORD` и `INIT_LIZA_PASSWORD`; после первого входа пароль можно сменить в профиле.

```bash
cp .env.example .env
# Задайте уникальные пароли в .env, затем экспортируйте переменные удобным способом.
npm start
```

Ручной запуск аудита за вчера:

```bash
DATA_DIR=/var/lib/agency-ops npm run audit:direct
```

Боевой таймер `agency-ops-direct-audit.timer` запускается ежедневно в 08:15 МСК. Токен Direct читается из защищённого файла, его значение не хранится в репозитории или базе CRM.

Файл `.env`, база SQLite и журналы исключены из Git. Боевые пароли и данные проектов в репозиторий не входят.

## Созвоны и будущая интеграция Plaud

Платформа хранит отдельную историю созвонов по каждой карточке. Новая карточка лида создаётся только тогда, когда в конце расшифровки есть отдельная фраза `Проект <название>`. Если активная карточка с таким нормализованным названием уже существует, созвон добавляется в неё без дубля.

Plaud Cloud пока не подключён. Для будущего коннектора подготовлен защищённый endpoint:

```http
POST /api/integrations/calls
Authorization: Bearer <INTEGRATION_TOKEN>
Content-Type: application/json

{
  "source": "plaud",
  "external_id": "unique-recording-id",
  "occurred_at": "2026-11-01T10:00:00Z",
  "title": "Первичный созвон",
  "summary": "Краткая сводка",
  "transcript": "Полная расшифровка.\nПроект Мария"
}
```

Без `INTEGRATION_TOKEN` endpoint отключён. Повторный `external_id` не создаёт дубль записи.
